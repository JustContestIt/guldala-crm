# Guldala CRM

Книга сезона тюльпанов: расчёт по сетке, брони, остатки по цветам, деньги, сообщения клиентам. Спецификация — `../GULDALA_CRM_SPEC.md`.

Next.js 16 (App Router) + Drizzle + Postgres 16 + Tailwind 4 + Vitest.

```bash
npm install
cp .env.example .env        # задать SESSION_SECRET и SEED_OWNER_PASSWORD
npm run db:up               # Postgres в Docker на 127.0.0.1:5433
npm run db:migrate
npm run db:seed             # стирает базу и заливает заглушки §18; вход: tatiana / SEED_OWNER_PASSWORD
npm run dev                 # http://localhost:3001
npm test                    # unit + интеграционные (на TEST_DATABASE_URL, база пересоздаётся)
npm run user:create -- tatiana "Татьяна"   # создать пользователя или сбросить пароль
```

Деплой на сервер — `deploy/README.md`.

**Не задавайте `WAZZUP_API_TOKEN` там, где есть seed-клиенты**: номера `+7777000000N` настоящие, «Отправить» уйдёт незнакомым людям. Тестовые отправки — только на свой номер.

## Решения, которых нет в спеке

- **Один Next.js вместо монорепо** NestJS + Vite (§15 разрешает).
- **scrypt вместо bcrypt** для пароля: стандартная библиотека Node, без зависимости.
- **Истечение броней — лениво**, перед каждой операцией и чтением списка (`expireHolds`). На этапе 4 ту же функцию будет вызывать cron раз в 15 минут.
- **Неоплаченный заказ пересчитывается по сетке** при открытии карточки и при записи оплаты: предоплата, внесённая после смены периода, считается по новой цене (§9).
- **Шаблон `booking`** без срока брони для `new` («проверю наличие и подтвержу») и «предоплата получена» для оплаченного; строка скидки, если она есть.
- **Отправка расчёта на новый номер** создаёт клиента с `source = inbound_message`: раз спросил цену, значит написал первым.
- **Wazzup: одна повторная попытка** при сетевой ошибке или 5xx. Повтор с тем же `crmMessageId` Wazzup не отправляет, а отвечает `400 REPEATED_CRM_MESSAGE_ID` (окно 60 с): значит, первая попытка дошла, считаем сообщение отправленным (без `messageId`). Ответ `201 {messageId, chatId}` проверен с настоящим аккаунтом 23.10.2026. Ошибки Wazzup — словами по коду из ответа (`wazzupError`), не JSON. Очередь `outbox` не понадобилась.
- **Заказ с сайта** (`created_by = client`, `channel = site`) при нехватке остатка не создаётся вовсе — спека §9 говорит «форма не даёт отправить», а `new` с нехваткой оставлен оператору. ТОО и БИН клиента пишутся в `comment_client` строкой: в `clients` таких полей нет (§6). Пуш Татьяне о заказе и лиде — строка `[site] …` в логе CRM до Telegram (H).
- **Лимит заявок с сайта** — 5 в час с номера и 20 с IP-адреса, счётчики в памяти процесса (`lib/ratelimit.ts`, `shortcut:`): один контейнер CRM.
- **Ссылка с предзаполнением** ведёт в каталог сайта `/tulpan/sorta?c=TOKEN` (с этапа C) и живёт в `conversations.prefill_token` 30 дней от `prefill_token_at`; состав заказа в ней не передаётся. Кнопка — в Composer на «Расчёте»: дописывает ссылку в текст ответа, дальше «Скопировать» / «Отправить».
- **`WAZZUP_TEST_PHONES`** (через запятую, `+7XXXXXXXXXX`): если задан, CRM работает только с этими чатами — одна проверка `chatAllowed` на отправку и приём. Отправка на другие номера не выполняется: сообщение со статусом `error`, событие в журнале, в логе «пропущено, не тестовый номер». Входящие и эхо из других чатов отбрасываются целиком: не сохраняются, клиент не создаётся, ассистент не отвечает и в OpenAI ничего не уходит; в логе только число пропущенных. Пусто — боевой режим.
- **Сайт и CRM — один compose и один Caddy** (`deploy/`): сайт собирается из соседнего репозитория `../../site`, хосты `DOMAIN` и `botanica.DOMAIN` → сайт, `crm.DOMAIN` → CRM. `PUBLIC_URL` не задаётся отдельно — это `https://crm.${DOMAIN}`, а `SITE_URL` (для ссылок на сайт) — `https://${DOMAIN}`. Сайт ходит в CRM по `http://app:3001` внутри сети Docker с общим `CRM_PUBLIC_SECRET`.
- **Главная `/` — доска заказов** (спека 5.1: «главная на телефоне — доска»), «Сегодня» живёт на `/today`. Переключатель — `?tab=board|list|money`, доска по умолчанию. Колонка «Готов к выдаче» скрыта, если статус выключен в сезоне и в ней пусто.
- **Доска без списка и «Денег», с перетаскиванием** (24.10.2026, решение Никиты; телефон в приоритете): карточку тянут в другой статус — на телефоне после удержания ~0,3 с (свайп по ленте по-прежнему прокручивает, тап открывает заказ), мышью сразу. Бросок = кнопка того же перехода: «Бронь» подтверждает или возобновляет; «Предоплачен» записывает предоплату по Kaspi или закрывает выставленный счёт; «Выдан» выдаёт при полной оплате, а с доплатой открывает заказ; зона «Отменить заказ» (появляется во время переноса над нижним меню) спрашивает причину. Своя реализация на pointer-событиях (`components/DragBoard.tsx`): HTML5 drag-and-drop не работает с пальца. У карточки остаётся кнопка следующего шага; поиск над доской.
- **Выдача с доплатой отменяет ожидающие счета заказа** — иначе поздняя отметка счёта дала бы переплату.
- **Частичная выдача** — только у `prepaid` / `ready`, без приёма денег (остаток — «Отметить оплату» или при полной выдаче). Если частичная выдача забирает всё, что осталось, это полная выдача: сначала остаток, потом `issued`. `confirmed` (при `issue_on_full_payment_allowed`) выдаётся только целиком с полной оплатой. Событие частичной выдачи — `edit` с `issued`; «Не приехал» — `note` с `noShow` (дата выдачи), заказ не меняется. Даты на экране — окно выдачи сезона и сегодня.
- **«Брали в прошлом сезоне, в этом нет»**: прошлый сезон — ближайший по `peak_date` до текущего; «брали» — заказы `issued`; «в этом не заказывали» — нет заказов, кроме `expired` / `cancelled`. В строке — что брали и «написали DD.MM» по последнему `season_open` (не `error`). «Написать» открывает карточку клиента с готовым текстом `season_open`: предпросмотр, правка, отправка по одному. Сообщение без заказа пишется только в `messages`, в журнал заказа не попадает.
- **Seed**: закрытый сезон «Тюльпаны 2026» с тремя выданными заказами и клиенты `+77770000008/9`, которые в 2027 не заказывали.
- **Вебхук Wazzup** (этап E): `/webhooks/wazzup/<WAZZUP_WEBHOOK_SECRET>`, секрет сверяется за постоянное время, чужой — 404. Ответ 200 сразу, запись в базу и ассистент — в `after()` из `next/server` (сбой — строка `[wazzup] webhook failed` в логе; Wazzup повторов не обещает). Принимаются только чаты WhatsApp канала `WAZZUP_CHANNEL_ID` (подписка одна на аккаунт, а у аккаунта может быть несколько каналов). Подписка — кнопка «Подписать вебхуки и проверить» в «Ещё → WhatsApp» (`connectChannel`: `PATCH` + `GET /v3/webhooks`, потом `GET /v3/channels`); нужен `PUBLIC_URL` — в compose это `https://crm.${DOMAIN}`.
- **Эхо нашей отправки** — дубль по `messageId`. Если эхо обогнало ответ Wazzup на отправку (строка ещё без `messageId`), оно подхватывается по тексту: исходящее CRM в том же чате без `messageId` за 10 минут. Остальное эхо — `author = operator`, `is_echo`, и в этом чате бот молчит (`assistant_muted_at`).
- **Статусы сообщений — только вперёд** (`queued → sent → delivered → read`, `error`). Статус, пришедший раньше, чем CRM записала `messageId` своей отправки, теряется — сообщение остаётся «отправлено». Правки и удаления сообщений в WhatsApp повторяют `messageId` и не отражаются. Оба — `shortcut:` в коде.
- **Состояние канала и время последнего вебхука** — таблица `app_state` (ключ → jsonb): `wazzup:channel` обновляют вебхук `channelsUpdates` и кнопка в настройках, `wazzup:webhook` — каждый вебхук. «Сегодня» показывает сохранённое, без запроса к Wazzup.
- **Переписка в карточке клиента** — последние 30 сообщений, без iFrame Wazzup. Не текст (фото, голосовое) — строка «[фото]» и ссылка в `attachments`.
- **«Написали, но заказа нет»** — входящее за 24 часа и нет заказа этого сезона в `new / confirmed / prepaid / ready` (выданный заказ не активный).
- **Ассистент** (этап F, спека §19): модель — OpenAI, `gpt-6.1-sol` по умолчанию (`OPENAI_MODEL`), Responses API, `reasoning.effort = low`, `store: false`. Режим `assistant_mode` — в форме сезона («Сезон → Даты и параметры»), по умолчанию `off`. Ответ всегда сначала строка `messages` со `status = draft`: в `draft` её отправляет Татьяна из карточки («Отправить» шлёт её же, как поправлена; «Удалить»), в `auto` её сразу отправляет `sendDraft`; новый черновик в чате заменяет неотправленный. Пауза 5 с после входящего, не больше 6 шагов модели, история — 30 сообщений. `assistant/*.md` читаются с диска на каждом ответе; в образ их кладёт сам Next (file tracing standalone).
- **Заказ бота** — `createSiteOrder(…, "whatsapp")`: тот же путь, что заказ с сайта, `created_by = client` (при нехватке не создаётся), `booking` уходит так же. Имя и магазин берутся из карточки клиента (их сохраняет `update_client`), телефон — из чата. Нехватку модель получает без чисел.
- **`handoff`** пишет строку в заметки клиента («ДД.ММ ЧЧ:ММ бот передал Татьяне: …») и `[assistant] handoff` в лог — до Telegram (H).
